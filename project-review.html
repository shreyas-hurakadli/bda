Student Performance Warning System

Big-data course project: ingest UCI student performance data on Hadoop HDFS, transform with Spark, expose analytics through Hive, and flag at-risk students using transparent, rule-based logic—not ML model accuracy.

Hadoop HDFS Apache Spark 3.5 Apache Hive 3.1 Docker / Podman

Goal

Build a review-ready pipeline that demonstrates classic data-engineering patterns: landing → curated → mart storage, distributed ETL, partitioned Parquet, external Hive tables, and SQL reports for academic intervention lists.

One-line pipeline

local CSV → HDFS landing → Spark curated Parquet → Spark features + risk flags → HDFS mart Parquet → Hive external tables/views → demo SQL warnings

Dataset

  • Source: UCI Student Performance (student+performance/student/)
  • Files: student-mat.csv (Math), student-por.csv (Portuguese), student.txt (dictionary)
  • Format: Semicolon-delimited CSV, header row, quoted strings; 33 shared columns including grades G1, G2, G3 (0–20)
  • Derived: Spark adds course_id = MAT or POR and unions both courses (~1044 rows after ingest)

Spark jobs

01 — Ingest & clean

Read CSVs from landing, normalize column names, cast types, add course_id and source_file. student_key is SHA-256 over demographic fields (anonymized join key, no PII).

02 — Build features

Course-level stats (avg G3, 75th percentile absences), school-level avg G3, plus grade_avg, grade_trend (G3 − G1), absence/study bands, support counts, ranks.

03 — Risk flags

Five boolean rules summed into risk_score, mapped to risk_level and human-readable warning_reasons.

Hive

Database student_warn with external tables over HDFS Parquet:

  • student_course_performance, student_features, risk_flags
  • Views: v_at_risk_students, v_course_risk_summary, v_school_risk_summary

Demo SQL (hive/04_demo_queries.hql) shows row counts, top at-risk students, course/school rollups, and per-rule contribution counts.

Run the demo locally

Host needs only Docker or Podman—Hadoop, Spark, and Hive run inside the project container. Runtime state goes to .runtime/ (gitignored).

bash scripts/demo_container.sh

Steps inside the container:

  1. Start single-node HDFS; init Derby Hive metastore
  2. Upload CSVs to landing
  3. Run three Spark jobs
  4. Create Hive tables/views; run demo queries

Review talking points

  • Medallion-style zones: raw landing vs typed curated vs analytics mart
  • Parquet + course_id partitioning for efficient course-scoped reads
  • Spark for scalable transforms; Hive as SQL layer over external files
  • Explainable rules—every flag inspectable in SQL and Spark code
  • Privacy: hashed student_key; views expose masked student_id_masked
